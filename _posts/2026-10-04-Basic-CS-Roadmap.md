## 0. Intro

CS를 어떻게 공부해야 하냐는 질문을 수도 없이 받았는데, 막상 전부 설명하려면 범위가 매우 넓습니다.

컴퓨터 구조, OS, 자료구조, 알고리즘, 네트워크, DB 전부 다 CS고, 이걸 처음부터 전부 병행하기엔 시간적으로도 체력적으로도 무리가 있습니다.

그래서 이번 글에서는 내가 작성한 코드가 컴퓨터에서 어떻게 실행되는지 이해하는 데 필요한 기초 CS 학습 순서를 소개하겠습니다.

시작하기 전에 C 언어의 기본은 익혀두는 편이 좋습니다. 변수, 함수, 배열, 포인터를 알고 간단한 프로그램을 작성할 수 있으면 충분합니다.

특히 C, C++, Rust처럼 메모리를 직접 다뤄야 하는 언어를 공부할 때 도움이 될 내용으로 구성했습니다.

처음부터 두꺼운 책이나 긴 강의를 끝까지 볼 필요는 없습니다. 아래 섹션을 하나씩 AI에 입력하고 초보자 눈높이로 설명해달라고 요청해보세요. 작은 연습 문제도 풀어보면 더 좋습니다.

## 1. 숫자와 메모리

먼저 컴퓨터가 숫자나 문자를 어떻게 저장하는지 살펴보겠습니다.

코드에서는 그냥 `int x = 10`처럼 값을 넣지만, 컴퓨터 안에서는 결국 수많은 `0`과 `1`로 저장됩니다.

bit와 byte의 의미를 익힌 뒤 2진수와 16진수로 넘어가면 됩니다. 그다음에는 정수와 실수가 컴퓨터 안에서 어떻게 표현되는지 살펴보세요.

같은 정수라도 저장할 공간은 한정되어 있기 때문에 무한히 큰 숫자를 저장할 수는 없습니다. 음수를 사용하는지에 따라서도 저장할 수 있는 숫자의 범위가 달라집니다.

실수는 조금 더 특이합니다. 우리가 사용하는 `0.1`, `0.2` 같은 숫자도 컴퓨터에서는 정확하게 표현하지 못하는 경우가 있습니다. 그래서 `0.1 + 0.2`를 계산했는데 생각했던 것과 조금 다른 값이 나오는 일도 생깁니다.

> 왜 타입마다 크기가 다르고 저장할 수 있는 값의 범위도 다른지, 그리고 코드에서 사용하는 값들이 결국 메모리 어딘가에 저장된다는 것까지 이해해야 합니다.

## 2. CPU와 Assembly

값이 메모리에 저장되는 방식을 알았다면, 이제 CPU가 그 값을 가져와 계산하고 다시 저장하는 과정을 따라가 보겠습니다.

우리는 `a + b`처럼 덧셈을 쓰고, `if`로 조건문을 만들고, 함수를 호출합니다. 하지만 CPU가 C나 C++ 문법을 그대로 읽고 실행하지는 않습니다.

우리가 작성한 코드는 CPU가 이해할 수 있는 단순한 명령으로 바뀝니다. CPU는 명령을 차례로 실행하며 값을 옮기고, 더하고, 비교하고, 메모리에서 데이터를 읽습니다.

이 과정을 따라가다 보면 Register, 명령어, 메모리 접근, 함수 호출 같은 개념을 만나게 됩니다.

이때 Assembly를 보면 도움이 됩니다. 직접 프로그램을 작성하기보다는 내가 쓴 코드가 CPU에 어떻게 보이는지 확인하는 도구로 활용해보세요.

처음에는 `RAX`, `EAX` 같은 레지스터가 무엇인지, `mov`, `add`, `cmp`, `jmp`, `call`, `ret`처럼 자주 보이는 명령이 대충 무슨 일을 하는지만 알면 충분합니다. 나머지는 필요할 때 찾아봐도 괜찮습니다.

> 간단한 코드를 보고 컴파일했을 때 CPU가 어떤 일을 해야 할지 대충 생각할 수 있으면 됩니다.

## 3. 코드와 메모리 연결하기

값의 저장과 계산을 살펴봤으니, 이번에는 평소 작성하던 코드를 실제 메모리와 연결해보겠습니다.

변수는 실제로 어디에 생길지, 함수 안에서 만든 변수는 함수가 끝난 뒤에도 남아 있을지, Pointer에 들어 있는 주소는 언제까지 사용할 수 있는지 등등. 평소 코드에서 보던 것들을 하나씩 짚어보는 것입니다.

이 과정에서 Stack과 Heap을 만납니다. Pointer와 Reference가 실제로 무엇을 가리키는지도 더 구체적으로 이해할 수 있습니다.

값이 만들어진 뒤 언제 사라지는지도 중요합니다. 메모리에 생성된 값이 프로그램이 끝날 때까지 남아 있는 것은 아닙니다. 이 시기를 설명하는 개념이 Lifetime입니다.

변수가 어디에 만들어지는지, 함수가 끝나면 어떤 값이 사라지는지, 어떤 주소를 알고 있다고 해서 그 메모리를 항상 읽어도 되는지를 생각해보면 됩니다.

이렇게 연결해서 보면 문법만 봤을 때는 귀찮아 보였던 규칙들이 실제로 어떤 문제를 막기 위한 것인지 보이기 시작합니다.

메모리 규칙은 복잡하므로 처음부터 깊게 파고들 필요는 없습니다. 작은 코드에서 값이 생성되고 사라지는 시점을 따라가 보세요.

> 값과 주소가 무엇이 다른지, 주소를 알고 있다고 해서 그 메모리를 언제나 사용할 수 있는 건 아닌 이유를 설명할 수 있으면 됩니다.

## 4. 소스 코드에서 실행 파일까지

지금까지는 이미 실행되고 있는 프로그램 안에서 무슨 일이 일어나는지를 봤습니다. 그런데 우리가 작성하는 코드는 처음부터 CPU가 실행할 수 있는 형태가 아닙니다.

이번에는 소스 코드를 작성하고 빌드 버튼을 누른 뒤 실행 파일이 만들어지기까지 어떤 일이 일어나는지 알아보겠습니다.

먼저 Compilation과 Linking의 차이를 익혀보세요. 그다음 Static Linking과 Dynamic Linking으로 범위를 넓히면 됩니다.

실행 파일의 내부 구조를 전부 외울 필요는 없습니다. 코드와 데이터가 있고, 다른 코드와 연결하기 위한 정보도 있다는 정도만 알면 됩니다.

여기까지 공부했다면 Compiler와 Linker가 서로 다른 일을 한다는 것부터 설명할 수 있으면 됩니다.

> 컴파일에는 성공했는데 링크 단계에서 실패할 수 있는 이유는 무엇일까요? 실행 파일 옆에 특정 라이브러리가 없으면 실행되지 않는 이유도 설명할 수 있어야 합니다.


## 5. 운영체제와 프로그램

실행 파일이 만들어졌다면, 다음은 운영체제 위에서 프로그램이 동작하는 방식입니다. 프로그램은 컴퓨터의 자원을 마음대로 사용할 수 없습니다. 그 사이에서 운영체제가 필요한 일을 맡습니다.

파일을 읽거나 네트워크를 사용하고, 메모리를 확보하는 일은 프로그램 혼자서 처리할 수 없습니다. 필요한 작업을 운영체제에 요청해야 합니다.

여기서는 System Call, Process, Thread, Virtual Memory, File I/O를 중심으로 공부하면 됩니다.

프로그램에서 사용하는 주소가 곧바로 실제 RAM의 물리 주소를 뜻하는 건 아니라는 것부터 이해하면 됩니다. 여러 프로그램이 동시에 실행돼도 각자 자기만의 메모리를 가진 것처럼 사용할 수 있게 OS가 관리한다는 점도 알아두세요.

처음부터 Page Table, Scheduler까지 들어갈 필요는 없습니다.

지금은 운영체제를 구현하려는 게 아니라, 내 프로그램이 운영체제 위에서 어떻게 실행되는지를 이해하는 게 목적입니다.

> 프로그램이 실행 중인 상태가 무엇인지, 메모리와 파일을 사용하려면 OS가 왜 필요한지를 설명할 수 있으면 됩니다.

## 6. 여러 작업이 동시에 실행될 때

여기까지 프로그램이 실행되는 기본 흐름을 살펴봤습니다. 이제 여러 Thread가 같은 데이터를 동시에 다루는 상황으로 넘어가겠습니다.

무작정 Thread를 여러 개 만든다고 모든 일이 빨라지는 건 아닙니다. 같은 데이터를 동시에 수정하면 실행 결과가 달라질 수도 있고, 서로를 기다리다가 아무것도 진행할 수 없게 될 수도 있습니다.

이 지점에서 Race Condition, Mutex, Atomic을 만나게 됩니다. CPU Cache까지 살펴보면 성능과 동기화가 왜 복잡한지도 이해할 수 있습니다.

Memory Ordering이나 Lock-free 자료구조까지 한 번에 들어가는 건 너무 깊습니다. 작은 공유 변수 하나를 안전하게 다루는 것부터 시작해도 배울 게 많습니다.

> 공유 데이터를 동시에 다룰 때 어떤 문제가 생기고, 동기화가 왜 필요한지를 이해해야 합니다.

## 7. Wrapping Up

지금까지의 흐름을 질문으로 정리해보겠습니다.

1. 값은 어떻게 저장될까요?
2. CPU는 그 값으로 어떻게 계산할까요?
3. 내 코드의 변수와 함수는 메모리에서 어떻게 보일까요?
4. 소스 코드는 어떻게 실행 파일이 될까요?
5. 실행된 프로그램은 OS와 어떻게 상호작용할까요?
6. 여러 작업이 동시에 실행되면 어떤 문제가 생길까요?

하나씩 전부 완벽하게 끝내고 다음으로 넘어갈 필요는 없습니다. 뒤쪽 내용을 보다가 앞쪽에서 이해가 안 됐던 부분이 풀리기도 합니다.

자료구조와 알고리즘은 별도로 공부하고, 네트워크나 데이터베이스는 만드는 프로그램에 맞춰 배우면 됩니다. 이 로드맵으로 CS 개념이 전부 끝나는 것은 아닙니다.

처음부터 모든 것을 알려고 하면 범위가 너무 넓습니다. 우선 내가 쓰는 코드 아래에서 무슨 일이 일어나는지 따라가 보세요. 설명하다 막히는 부분을 하나씩 채워 가면 됩니다.
