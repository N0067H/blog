## 0. Intro

C++는 40년 가까이 하위 호환성을 지키면서 문법이 복잡해졌고, Memory Safety 문제도 해결하기 어렵다는 비판을 받고 있습니다.

특히 Dangling Pointer, Use-after-free, Out-of-bounds 같은 문제는 조금만 실수해도 바로 Undefined Behavior로 이어지는데, 이걸 언어 차원에서 완전히 막기도 어렵습니다.

그래서 기존 C++ 코드베이스를 Rust 같은 Memory Safe 언어로 옮겨야 한다는 이야기도 나왔습니다.

이번에 소개할 **cppfront**도 이런 문제를 해결하려는 시도입니다. ISO C++ 표준 위원회 의장이었던 Herb Sutter가 기존 생태계는 유지하면서 문법을 새로 설계하자고 제안했습니다.

cppfront는 새로운 문법으로 작성한 코드를 기존 C++ 코드로 변환합니다. 변환된 코드는 원래 쓰던 C++ 컴파일러가 컴파일합니다.

이런 구조라서 cppfront는 일반적인 컴파일러보다 Source-to-Source Compiler나 Transpiler에 가깝습니다. TypeScript 코드를 JavaScript로 바꿔 쓰는 방식과 비슷합니다.

**cppfront**라는 이름은 Bjarne Stroustrup이 처음 C++을 구현할 때 만든 **cfront**에서 따온 것 같습니다. cfront도 C++ 코드를 C 코드로 변환했으니 방식까지 닮았습니다.

이 새로운 문법은 **Cpp2**라고도 부릅니다. 기존 C++ 문법은 **Cpp1**로 구분합니다.

Cpp2는 기존 C++ 코드와 생태계 위에 더 단순하고 안전한 문법을 추가합니다. C++을 점진적으로 발전시켜 보자는 실험입니다.

## 1. Philosophy

CppFront가 어떤 방향으로 C++을 바꾸려는지 알아봅시다.

핵심 목표는 C++을 더 단순하고 안전하게 만드는 것입니다. Compiler나 IDE가 코드를 다루기 쉬운 문법도 중요하게 봅니다.

하지만 C++에는 수십 년 동안 쌓인 코드와 라이브러리가 있습니다. 불편한 문법을 고치더라도 이 생태계를 무시할 수는 없습니다.

CppFront는 이 코드들을 사용할 수 있도록 설계합니다.

기존 C++에서 권장 사항에 머물렀던 규칙도 언어의 기본 동작으로 가져오려 합니다. C++ Core Guidelines의 안전한 Parameter Passing이나 초기화 방식이 대표적입니다.

### 1.1. 하위 호환성을 포기하지 않는 진화

CppFront는 기존 C++ 코드와 라이브러리를 활용하면서 새로운 문법을 더합니다. JavaScript 생태계 위에서 TypeScript를 쓰는 모습과 비슷합니다.

기존 C++ 표준 라이브러리나 서드파티 라이브러리도 사용할 수 있습니다.

별도의 FFI나 Binding, Wrapping 없이 Cpp1 코드와 Cpp2 코드를 섞어 쓰는 것이 목표입니다.

프로젝트 전체를 다시 작성할 필요는 없습니다. 새로 만드는 부분부터 Cpp2를 적용할 수 있습니다.

오래된 코드베이스가 많은 C++ 생태계에서는 꽤 현실적인 접근입니다.

### 1.2. 올바른 행동을 기본값으로

기존 C++에는 하위 호환성의 흔적이 곳곳에 남아 있습니다.

초기화 규칙부터 implicit conversion, pointer, reference, const, move semantics까지 제대로 쓰려면 신경 써야 할 게 한두 개가 아닙니다.

함수 Parameter만 봐도 드러납니다.

값으로 받을지, `const T&`, `T&`, `T&&` 중 무엇을 쓸지 직접 정해야 합니다. 값을 어떻게 사용할지뿐 아니라 C++에서 어떤 방식으로 전달할지까지 고민해야 합니다.

Cpp2에서는 Parameter를 어떻게 사용할지부터 표현합니다.

값을 읽기만 한다면 `in`, 수정한다면 `inout`, 함수에서 값을 만들어 호출자에게 전달한다면 `out`, 소유권을 넘긴다면 `move`, Perfect Forwarding이 필요하다면 `forward`를 사용합니다.

실제 C++의 Parameter Passing 방식으로 옮기는 일은 cppfront가 맡습니다.

반환값도 기본적으로 무시할 수 없습니다. 기존 C++에서 `[[nodiscard]]`를 일일이 붙이던 것과 비교하면 기본값이 반대입니다.

Parameter의 기본 모드인 `in`은 읽기 전용입니다. Member Function의 `this`도 기본적으로 `in`이라 const처럼 취급됩니다. 하지만 Local Variable까지 전부 immutable로 만들지는 않습니다.

Rust처럼 모든 변수를 못 바꾸게 해두고 필요할 때 `mut`를 붙이는 방식과는 다릅니다. Cpp2는 함수와 객체 사이에서 값이 어떻게 사용되는지 표현하는 데 초점을 둡니다.

### 1.3. Memory Safety 강화

C++에서 Pointer를 잘못 다루면 꽤 쉽게 Dangling Pointer나 Use-after-free를 만들 수 있습니다. 배열 인덱스를 잘못 계산하면 Out-of-bounds가 나기도 합니다.

이런 실수는 명확한 에러 없이 Undefined Behavior로 이어지기도 합니다.

CppFront는 이런 문제 중 상당수를 언어 차원에서 잡으려 합니다.

초기화되지 않은 값을 사용하는 것을 막고, 배열이나 컨테이너에 접근할 때 Bounds Checking을 적용합니다. Null Pointer Dereference나 Integer Division by Zero처럼 흔히 실수할 수 있는 동작도 검사 대상입니다.

하드웨어나 메모리를 직접 다루려면 위험한 연산이 필요할 때도 있습니다.

그래서 **위험한 동작을 하고 있다는 사실이 코드에 드러나게 만드는 쪽**을 택합니다.

안전하지 않은 Cast를 쓰려면 프로그래머가 의도적으로 안전 규칙을 벗어났다는 점을 명시해야 합니다.

Rust의 `unsafe`가 떠오를 수 있습니다. CppFront는 여러 안전 규칙을 한꺼번에 해제하기보다 필요한 규칙만 좁게 해제하는 방향을 지향합니다.

야매로 풀자면 **안전한 코드가 기본이고, 위험한 짓을 할 거면 티 내면서 해라** 정도입니다.

### 1.4. Machine-friendly 문법 단순화

기존 C++ 문법은 사람에게도 어렵지만 Parser 입장에서도 썩 반가운 언어는 아닙니다.

Context-sensitive한 문법이 많아서 코드 일부만 보고는 의미를 알 수 없는 경우가 있습니다. 주변 선언이나 문맥까지 봐야 합니다.

Compiler야 어떻게든 처리한다고 쳐도 IDE, Formatter, Static Analyzer 같은 툴을 만드는 입장에서는 꽤 골치 아픈 특성입니다.

CppFront는 이런 부분도 단순하게 만들려고 합니다.

선언 문법이 대표적인 예입니다.

기존 C++에서는

`int add(int a, int b)`

처럼 반환 타입부터 시작하지만 Cpp2에서는

`add: (a: int, b: int) -> int`

처럼 이름부터 시작합니다.

변수도 마찬가지입니다.

`x: int = 42`

처럼 `이름: 타입 = 값` 순서로 통일합니다.

사람이 왼쪽에서 오른쪽으로 읽기 편하고, Parser도 다음에 나올 문법을 예측하기 쉬워집니다.

Cpp2 문법에서는 Preprocessor나 Macro처럼 Parsing을 복잡하게 만드는 기능도 최대한 피합니다. 대신 기존 C++의 현대적인 기능을 활용합니다.

Cpp2 문법이 C++과 크게 달라진 데는 이런 이유가 있습니다. 사람이 읽기 편해야 하고, Compiler나 IDE도 코드를 쉽게 다룰 수 있어야 합니다.


## 2. Syntax

이제 실제 문법을 알아봅시다.

처음 보면 C++보다 Rust, Swift, TypeScript 같은 언어가 먼저 떠오릅니다.

그래도 결국 C++ 코드로 변환되기 때문에 기존 C++의 개념이 곳곳에 남아 있습니다.

### 2.1. 변수 및 객체

변수 선언은 `name: type = value` 순서로 작성합니다.

```cpp
x: int = 42;
name: std::string = "Cpp2";
```

타입을 굳이 적고 싶지 않으면 `:=`를 이용해서 타입을 추론할 수도 있습니다.

```cpp
x := 42;
name := "Cpp2";
```

기존 C++의 `auto`와 비슷한 역할입니다.

C++의 `int x = 42`, `int x(42)`, `int x{42}`처럼 초기화 방법이 여러 개로 갈라지는 대신, 선언과 초기화 문법을 최대한 일관되게 유지하려고 합니다.

### 2.2. 함수

함수도 변수처럼 이름부터 시작합니다.

```cpp
add: (a: int, b: int) -> int = {
    return a + b;
}
```

기존 C++과 순서가 반대입니다.

C++에서는 반환 타입부터 읽어야 하지만 Cpp2에서는 `add라는 함수가 int 두 개를 받고 int를 반환한다`는 순서로 읽을 수 있습니다.

반환 타입을 추론하게 만들 수도 있습니다.

```cpp
square: (x: int) -> _ = {
    return x * x;
}
```

`main`도 특별할 건 없습니다.

```cpp
main: () -> int = {
    std::println("Hello, CppFront!");
    return 0;
}
```

### 2.3. 파라미터

Parameter는 Cpp2에서 특히 흥미로운 부분입니다.

기존 C++에서는 Parameter 하나를 넘기는 데도 `T`, `T&`, `const T&`, `T&&` 같은 걸 직접 결정해야 했습니다.

Cpp2에서는 Pointer나 Reference를 고르기 전에 Parameter의 **용도**를 표현합니다.

- `in`: 읽기 전용. 기본값입니다.
- `inout`: 값을 읽고 수정합니다.
- `out`: 함수에서 값을 만들어 호출자에게 전달합니다.
- `move`: 값을 소비하고 소유권을 넘깁니다.
- `forward`: Perfect Forwarding에 사용합니다.

읽기만 한다면 이렇게 작성합니다.

```cpp
print_val: (x: int) = {
    std::println("{}", x);
}
```

`in`이 기본값이라 굳이 적을 필요도 없습니다.

값을 수정해야 한다면 그때 `inout`을 사용합니다.

```cpp
increment: (inout x: int) = {
    ++x;
}
```

함수가 Parameter를 어떻게 사용하는지 기존 C++의 Reference 표기보다 직접적으로 보입니다.

### 2.4. 클래스 및 타입

새로운 타입은 `type`으로 정의합니다.

```cpp
point: type = {
    x: int = 0;
    y: int = 0;

    print: (this) = {
        std::println("({}, {})", this.x, this.y);
    }
}
```

여기서 `this`를 눈여겨볼 만합니다. Cpp2에서는 이것도 Parameter로 취급합니다.

Member Function은 `this`라는 Parameter를 하나 더 받는 함수처럼 다룹니다.

그래서 `this`에도 `in`, `inout`, `move` 같은 Parameter 규칙을 그대로 적용할 수 있습니다.

객체를 수정하는 Member Function은 다음처럼 작성합니다.

```cpp
move_x: (inout this, dx: int) = {
    this.x += dx;
}
```

기존 C++에서 함수 뒤에 `const`를 붙이거나 ref-qualifier를 붙이던 것보다, 이 함수가 객체를 수정하는지 여부가 훨씬 앞에 드러납니다.

### 2.5. 조건문과 제어 흐름

마지막으로 조건문과 제어 흐름을 보겠습니다. `if`는 크게 특별하지 않습니다.

```cpp
if x > 10 {
    std::println("Greater");
}
```

괄호 없이 조건식을 바로 작성합니다.

기존 C++의 `switch`보다 강력한 `inspect`도 있습니다.

```cpp
inspect x -> std::println(_);
```

`inspect`는 값의 형태를 분석해 비교하는 Pattern Matching에 가깝습니다.

특히 C++의 `std::variant` 같은 타입을 다룰 때 기존의 `std::visit`보다 훨씬 자연스럽게 표현할 수 있습니다.

## 3. Wrapping Up

CppFront의 방향과 기본 문법을 알아봤습니다. 문법만 보면 기존 C++과 거리가 멀어 보입니다.

하지만 이 코드도 결국 기존 C++ 코드로 변환됩니다. C++ 컴파일러와 STL, 라이브러리도 그대로 사용합니다.

문법 아래에는 여전히 C++이 있습니다.

cppfront는 기존 C++ 위에 새 문법을 올리는 실험입니다. "하위 호환성 때문에 C++ 문법을 못 고치겠으면 문법을 하나 더 만들자"는 발상인 셈입니다.
