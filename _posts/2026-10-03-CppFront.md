## 0. CppFront

C++는 거의 40년이 넘게 하위 호환성을 유지한답시고 문법이 괴랄해지고 있고, Memory Safety도 해결하기 어렵다는 비판을 많이 받고 있다.

특히 Dangling Pointer, Use-after-free, Out-of-bounds 같은 문제는 조금만 실수해도 바로 Undefined Behavior로 이어지는데, 이걸 언어 차원에서 완전히 막기도 어렵다.

그래서 한동안은 기존 C++ 코드베이스를 Rust 같은 Memory Safe 언어로 전환해야 한다는 이야기도 꽤 많이 나왔다.

아무튼 이런 문제를 해결하고 싶었던 ISO C++ 표준 위원회 의장이었던 Herb Sutter가 문법을 새로 짜되, 기존 C++ 생태계를 그대로 가져간다는 **cppfront**를 제안했다.

cppfront는 새로운 문법으로 코드를 작성하면 이를 기존 C++ 코드로 변환한 다음, 우리가 원래 쓰던 C++ 컴파일러가 컴파일하는 구조다.

그래서 cppfront를 컴파일러라고 부르기에는 조금 애매하고, Source-to-Source Compiler나 Transpiler에 더 가깝다. TypeScript 코드를 JavaScript로 변환해서 기존 JavaScript 생태계를 그대로 사용하는 것과 꽤 비슷하다.

**cppfront**라는 이름은 Bjarne Stroustrup이 처음 C++을 구현할 때 만들었던 **cfront**에서 오마주해온 것 같다. cfront도 당시 C++ 코드를 C 코드로 변환해주는 방식이었으니 하는 짓도 묘하게 비슷하다.

다른 말로 **Cpp2**라고도 부른다. 기존 C++ 문법을 **Cpp1**이라고 부르고, 새로운 문법을 **Cpp2**라고 구분한다.

그렇다고 Cpp2가 C++을 버리고 새 언어로 갈아타자는 프로젝트는 아니고, 오히려 그 반대에 가깝다.

기존 C++ 코드와 생태계는 그대로 두고, 그 위에 더 단순하고 안전한 문법을 하나 추가해서 C++ 자체를 점진적으로 발전시켜 보자는 실험이다.

## 1. Philosophy

**CppFront**의 철학이라고 하면 C++을 훨씬 더 단순하게, 그만큼 더 안전하게, 그리고 툴링하기 쉽게 만드는 것이다.

그렇다고 수십 년 동안 쌓인 C++ 생태계를 전부 갈아엎을 수도 없는 노릇이다.

때문에 기존 C++에서 이미 좋은 습관이라고 알려진 것들만 단순 권장사항으로 남기는 대신, 아예 언어의 기본 규칙으로 끌어오는 방식을 많이 취한다.

특히 C++ Core Guidelines에서 권장하던 안전한 Parameter Passing이나 초기화 방식 등을 문법 자체에 녹여내려고 한다.

### 1.1. 하위 호환성을 포기하지 않는 진화

Rust, Carbon 같은 언어들이 새로운 언어와 생태계를 만들어 C++의 자리를 가져오려고 한다면, cppfront는 기존 C++ 생태계와 공존하는 것을 중요하게 여긴다.

JavaScript 위에 TypeScript라는 좀 더 안전한 문법을 씌운 것처럼, Cpp2도 기존 C++ 위에 새로운 문법을 하나 더 씌운다고 생각하면 편하다.

덕분에 Cpp2를 쓴다고 기존 C++ 표준 라이브러리나 수많은 서드파티 라이브러리를 포기할 필요가 없다.

별도의 FFI나 Binding, Wrapping 작업 없이 기존 C++ 코드를 Cpp2에서 사용하는 것을 목표로 하고, 반대로 Cpp2 코드 역시 기존 C++ 코드와 자연스럽게 섞어서 사용할 수 있도록 한다.

결국 기존 프로젝트를 하루아침에 전부 Cpp2로 다시 작성하자는 게 아니다. 기존 C++ 코드는 그대로 두고, 새로 작성하는 부분부터 Cpp2를 조금씩 섞어 쓰는 방식도 가능하게 만들겠다는 것이다.

수십 년짜리 C++ 코드베이스가 널려 있는 현실을 생각하면 꽤 C++다운 접근이다.

### 1.2. 올바른 행동을 기본값으로

기존 C++는 과거의 하위 호환성을 지킨답시고 지금 기준으로 보면 위험하거나 복잡한 동작이 기본값인 경우가 꽤 많다.

초기화 규칙부터 시작해서 implicit conversion, pointer, reference, const, move semantics 등등..

특히 함수 하나 만들 때도 값을 받을 건지, `const T&`로 받을 건지, `T&`로 받을 건지, `T&&`로 받을 건지 고민해야 한다.

Cpp2에서는 이런 걸 구현 방법이 아니라 **의도**를 중심으로 표현하려고 한다.

값을 읽기만 할 거면 `in`, 수정할 거면 `inout`, 함수에서 값을 만들어 돌려줄 거면 `out`, 소유권을 넘길 거면 `move`, perfect forwarding이 필요하면 `forward` 같은 식이다.

프로그래머는 Parameter로 무엇을 할 건지만 적고, 실제 C++에서 어떤 방식으로 넘길지는 cppfront가 알아서 처리한다.

또 함수의 반환값도 기본적으로 무시할 수 없다. 기존 C++의 `[[nodiscard]]`가 기본적으로 붙어 있다고 생각하면 얼추 비슷하다.

다만 Cpp2의 모든 변수가 기본적으로 immutable인 것은 아니다.

Parameter의 기본 모드인 `in`은 읽기 전용이고 Member Function의 `this` 역시 기본적으로 `in`이라 const 취급되지만, 일반적인 Local Variable까지 전부 immutable로 고정하는 방식은 아니다.

즉 Rust처럼 "일단 전부 immutable이고 수정하려면 `mut` 붙이세요"라기보다는, 함수와 객체 사이에서 값이 어떻게 사용되는지를 좀 더 명확하게 표현하는 쪽에 가깝다.

### 1.3. Memory Safety 강화

C++는 매우 강력한 언어지만 한순간의 실수로 Dangling Pointer, Use-after-free, Out-of-bounds 같은 걸 만들어내기 딱 좋다.

그리고 이런 실수 대부분이 친절하게 에러를 뱉는 것도 아니고 그대로 Undefined Behavior로 넘어가 버린다.

CppFront는 이런 문제를 최대한 언어 차원에서 잡으려고 한다.

초기화되지 않은 값을 사용하는 것을 막고, 배열이나 컨테이너에 접근할 때 Bounds Checking을 적용하고, Null Pointer Dereference나 Integer Division by Zero처럼 흔하게 발생하는 문제도 검사한다.

물론 C++인데 Low-level 작업을 아예 못 하게 막아버릴 수는 없다.

대신 위험한 동작이 필요하다면 그 부분을 코드에 명시적으로 드러내는 방향을 택한다. 안전하지 않은 Cast 같은 작업을 아무렇지 않게 섞어 쓰는 대신, 프로그래머가 "여기서는 내가 알고 일부러 이러는 거임"이라고 명시해야 하는 식이다.

Rust의 `unsafe`와 비슷한 생각이 떠오르지만, 하나의 `unsafe` 블록 안에서 이것저것 다 허용하는 것보다는 필요한 안전 규칙만 좁게 해제하는 방향을 지향한다.

야매로 풀자면 **안전한 코드가 기본, 위험한 짓은 티를 내면서 해라** 정도로 이해하면 된다.

### 1.4. Machine-friendly 문법 단순화

기존 C++ 문법은 인간에게도 난해하지만 컴파일러나 IDE 입장에서도 별로 친절하지 않다.

Context-sensitive한 문법이 워낙 많아서 코드를 제대로 해석하려면 주변 문맥을 같이 봐야 하는 경우가 많고, 이것 때문에 Parser나 Static Analyzer 같은 툴을 만드는 것도 상당히 귀찮아진다.

CppFront는 함수 선언이나 변수 선언 등을 최대한 **Left-to-Right**로 읽히도록 통일했다.

기존 C++의 `int add(int a, int b)` 대신 `add: (a: int, b: int) -> int`처럼 이름부터 시작해서 Parameter와 Return Type 순서로 읽는다.

변수 역시 `x: int = 42`처럼 `이름: 타입 = 값`이라는 상당히 직관적인 순서를 따른다.

덕분에 인간이 읽기도 편하지만, Parser 입장에서도 기존 C++보다 훨씬 예측하기 쉬운 문법이 된다.

Preprocessor나 Macro처럼 C++의 Parsing을 더 환장하게 만드는 기능 역시 Cpp2 문법 안에서는 최대한 피하고, 기존 C++의 현대적인 기능을 활용하는 방향으로 간다.

결국 문법을 예쁘게 만드는 것뿐만 아니라, Compiler나 IDE, Formatter, Static Analyzer 같은 툴이 코드를 좀 덜 고통스럽게 이해할 수 있도록 만드는 것도 중요한 목표다.

## 2. Syntax

여기까지 TL;DR인 것 같으니 어서 실제 문법을 보자.

처음 보면 C++보다는 Rust, Swift, TypeScript 같은 비교적 현대적인 언어들이 먼저 떠오른다.

그래도 결국 C++로 내려가기 때문에 자세히 보면 C++의 개념들이 그대로 숨어 있다.

### 2.1. 변수 및 객체

변수 선언은 `name: type = value` 순서다.

```cpp
x: int = 42;
name: std::string = "Cpp2";
```

타입을 굳이 적고 싶지 않으면 `:=`를 이용해서 타입을 추론할 수도 있다.

```cpp
x := 42;
name := "Cpp2";
```

기존 C++의 `auto`와 비슷한 역할이라고 생각하면 된다.

C++의 `int x = 42`, `int x(42)`, `int x{42}`처럼 초기화 방법이 여러 개로 갈라지는 대신, 선언과 초기화 문법을 최대한 일관되게 유지하려고 한다.

### 2.2. 함수

함수도 변수와 마찬가지로 이름부터 시작한다.

```cpp
add: (a: int, b: int) -> int = {
    return a + b;
}
```

기존 C++과 비교하면 순서가 완전히 뒤집혔다.

C++에서는 반환 타입부터 읽어야 하지만 Cpp2에서는 `add라는 함수가 int 두 개를 받고 int를 반환한다`는 순서로 그냥 왼쪽에서 오른쪽으로 읽으면 된다.

반환 타입을 추론하게 만들 수도 있다.

```cpp
square: (x: int) -> _ = {
    return x * x;
}
```

`main`도 특별할 건 없다.

```cpp
main: () -> int = {
    std::println("Hello, CppFront!");
    return 0;
}
```

### 2.3. 파라미터

Cpp2에서 꽤 재미있는 부분이다.

기존 C++에서는 Parameter 하나를 넘기는 데도 `T`, `T&`, `const T&`, `T&&` 같은 걸 직접 결정해야 했다.

Cpp2에서는 Pointer나 Reference를 어떻게 쓸지보다 이 Parameter를 **어떤 용도로 사용할 건지**를 먼저 표현한다.

- `in`: 읽기 전용. 기본값이다.
- `inout`: 값을 읽고 수정한다.
- `out`: 함수에서 값을 만들어 호출자에게 전달한다.
- `move`: 값을 소비하고 소유권을 넘긴다.
- `forward`: Perfect Forwarding에 사용한다.

예를 들어 읽기만 한다면 그냥 이렇게 작성하면 된다.

```cpp
print_val: (x: int) = {
    std::println("{}", x);
}
```

`in`이 기본값이라 굳이 적을 필요도 없다.

값을 수정해야 한다면 그때 `inout`을 사용한다.

```cpp
increment: (inout x: int) = {
    ++x;
}
```

기존 C++의 Reference나 const Reference를 직접 설계하는 것보다 함수가 Parameter를 어떻게 사용하는지가 훨씬 직접적으로 보인다.

### 2.4. 클래스 및 타입

Cpp2에서는 새로운 타입을 `type`으로 정의한다.

```cpp
point: type = {
    x: int = 0;
    y: int = 0;

    print: (this) = {
        std::println("({}, {})", this.x, this.y);
    }
}
```

여기서도 `this`가 그냥 Parameter처럼 취급된다.

이게 꽤 중요한 특징인데, Member Function을 뭔가 특별한 함수로 취급하기보다는 `this`라는 Parameter를 하나 더 받는 함수처럼 다룬다.

그래서 `this`에도 `in`, `inout`, `move` 같은 Parameter 규칙을 그대로 적용할 수 있다.

객체를 수정하는 Member Function이라면 대충 이런 느낌이다.

```cpp
move_x: (inout this, dx: int) = {
    this.x += dx;
}
```

기존 C++에서 함수 뒤에 `const`를 붙이거나 ref-qualifier를 붙이던 것보다, 이 함수가 객체를 수정하는지 여부가 훨씬 앞에 드러난다.

### 2.5. 조건문과 제어 흐름

기본적인 `if`는 크게 특별하지 않다.

```cpp
if x > 10 {
    std::println("Greater");
}
```

괄호 없이 조건식을 바로 작성한다.

그리고 기존 C++의 `switch`보다 좀 더 강력한 기능으로 `inspect`가 있다.

```cpp
inspect x -> std::println(_);
```

`inspect`는 단순히 정수 하나 비교하는 `switch`를 예쁘게 만든 정도가 아니라, 값의 형태를 분석해 비교하는 Pattern Matching에 가까운 기능이다.

특히 C++의 `std::variant` 같은 타입을 다룰 때 기존의 `std::visit`보다 훨씬 자연스럽게 표현할 수 있다.

## 3. Wrapping Up

아무튼 여기까지 문법만 보면 C++과는 거리가 멀어도 너무 멀다는 생각이 들 수도 있다.

근데 재미있는 점은 결국 이 코드가 기존 C++ 코드로 내려가고, 기존 C++ 컴파일러와 STL, 라이브러리를 그대로 사용한다는 것이다.

문법은 꽤 과감하게 뜯어고쳤는데 그 아래에는 여전히 C++이 있는 셈이다.

그래서 cppfront는 C++을 버리고 새로 시작하는 언어라기보다는, "하위 호환성 때문에 C++ 문법을 못 고치겠으면 문법을 하나 더 만들자" 라는 과감한 실험에 가깝다고 볼 수 있다.
