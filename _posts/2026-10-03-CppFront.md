## 0. Intro

C++는 40년 가까이 하위 호환성을 지켜 왔다. 예전 코드가 계속 돌아가는 건 좋은데, 그동안 문법도 복잡해졌다. Memory Safety 문제도 늘 따라다닌다.

Dangling Pointer, Use-after-free, Out-of-bounds 같은 건 조금만 잘못 건드려도 Undefined Behavior로 이어진다. 포인터 수명이나 배열 범위를 매번 사람이 확인해야 하니 실수하기 쉽다. 언어 차원에서 전부 막기도 어렵고.

그래서 기존 C++ 코드베이스를 Rust 같은 Memory Safe 언어로 옮겨야 한다는 이야기도 많이 나온다.

**cppfront**도 이 문제를 어떻게든 풀어 보려는 시도다. ISO C++ 표준 위원회 의장이었던 Herb Sutter가 기존 생태계는 두고 문법을 새로 설계해 보자고 제안했다.

cppfront는 새로운 문법으로 작성한 코드를 기존 C++ 코드로 변환한다. 변환된 코드는 원래 쓰던 C++ 컴파일러가 컴파일한다.

그래서 cppfront는 Source-to-Source Compiler나 Transpiler에 가깝다. 비유하면 TypeScript를 JavaScript로 바꿔 쓰는 것과 비슷하다.

**cppfront**라는 이름은 Bjarne Stroustrup이 처음 C++을 구현할 때 만든 **cfront**에서 따온 것 같다.

이 새로운 문법은 **Cpp2**라고도 부르고 기존 C++ 문법은 **Cpp1**로 구분한다.

기존 C++ 위에 더 단순하고 안전한 문법을 얹어 보자는 실험이다.

## 1. Philosophy

그럼 문법을 새로 만들어서 뭘 바꾸려는 걸까?

문법을 줄이고 안전 검사를 기본으로 넣자는 거다. 컴파일러나 IDE가 코드를 읽기 쉽게 만드는 것도 목표다.

하지만 C++에는 수십 년 동안 쌓인 코드와 라이브러리가 있기 때문에 불편한 문법을 고치더라도 이 생태계를 무시할 수는 없다.

이미 있는 코드는 계속 쓸 수 있어야 한다. 이걸 버리면 시작부터 일이 너무 커진다.

기존 C++에서 권장 사항에 머물렀던 규칙도 언어의 기본 동작으로 가져오려고 한다. C++ Core Guidelines의 안전한 Parameter Passing이나 초기화 방식이 대표적이다.

### 1.1. 하위 호환성을 포기하지 않는 진화

CppFront는 기존 C++ 코드와 라이브러리를 활용하면서 새로운 문법을 더한다. JavaScript 생태계 위에서 TypeScript를 쓰는 모습과 비슷하다.

기존 C++ 표준 라이브러리나 서드파티 라이브러리도 사용할 수 있다.

별도의 FFI나 Binding, Wrapping 없이 Cpp1 코드와 Cpp2 코드를 섞어 쓰는 것이 목표다.

프로젝트를 통째로 갈아엎을 필요는 없다. 새로 만드는 부분부터 Cpp2로 써 보자는 식이다.

오래된 코드를 두고 새 코드부터 바꿀 수 있으니 적용하기도 편하다.

### 1.2. 올바른 행동을 기본값으로

기존 C++에는 하위 호환성의 흔적이 곳곳에 남아 있다.

초기화 규칙부터 implicit conversion, pointer, reference, const, move semantics까지 제대로 쓰려면 신경 써야 할 게 한두 개가 아니다.

당장 함수 Parameter만 봐도 그렇다.

값으로 받을지, `const T&`로 받을지, `T&`나 `T&&`가 필요한지 직접 골라야 한다. 그냥 값을 하나 넘기려는데 생각할 게 많다. 어떻게 쓸 값인지에 더해 전달 방식까지 챙겨야 한다.

Cpp2에서는 이 값을 어디에 쓸 건지부터 적는다.

값을 읽기만 한다면 `in`, 수정한다면 `inout`, 함수에서 값을 만들어 호출자에게 전달한다면 `out`, 소유권을 넘긴다면 `move`, Perfect Forwarding이 필요하다면 `forward`를 사용한다.

그걸 실제 C++의 Parameter Passing 방식으로 옮기는 건 cppfront가 알아서 한다.

반환값도 기본적으로 무시할 수 없다. 기존 C++에서 `[[nodiscard]]`를 일일이 붙이던 것과 비교하면 기본값이 반대다.

Parameter의 기본 모드인 `in`은 읽기 전용이다. Member Function의 `this`도 기본적으로 `in`이라 const처럼 취급된다. 하지만 Local Variable까지 전부 immutable로 만들지는 않는다.

Rust처럼 모든 변수를 못 바꾸게 해두고 필요할 때 `mut`를 붙이는 방식과는 다르다. Cpp2에서는 함수가 값을 읽는지, 수정하는지, 넘겨받는지를 적는다.

### 1.3. Memory Safety 강화

C++에서 Pointer를 잘못 다루면 쉽게 Dangling Pointer나 Use-after-free를 만들 수 있다. 배열 인덱스를 잘못 계산하면 Out-of-bounds가 나기도 한다.

잘못 썼다고 에러라도 깔끔하게 나오면 좋겠지만, 그냥 Undefined Behavior로 넘어가기도 한다.

CppFront는 이런 문제를 언어 차원에서 잡으려 한다.

초기화되지 않은 값을 사용하는 것을 막고, 배열이나 컨테이너에 접근할 때 Bounds Checking을 적용한다. Null Pointer Dereference나 Integer Division by Zero처럼 흔히 실수할 수 있는 동작도 검사 대상이다.

그렇다고 위험한 연산을 전부 막을 수도 없다. 하드웨어나 메모리를 직접 만지다 보면 필요한 순간이 있다.

그래서 **위험한 동작을 하고 있다는 사실이 코드에 드러나게 만드는 쪽**을 택한다.

안전하지 않은 Cast를 쓰려면 프로그래머가 의도적으로 안전 규칙을 벗어났다는 점을 명시해야 한다.

Rust의 `unsafe`가 떠오를 텐데, CppFront는 필요한 안전 규칙만 좁게 해제하려고 한다. 여러 규칙을 한꺼번에 풀어 버리는 식은 피하자는 거다.

대충 풀면 **안전하게 쓰는 게 기본이고, 위험한 짓을 할 거면 티는 내라** 정도다.

### 1.4. Machine-friendly 문법 단순화

기존 C++ 문법은 사람에게도 어렵지만 Parser 입장에서도 반가운 언어는 아니다.

Context-sensitive한 문법이 많아서 코드 일부만 보고는 의미를 알 수 없는 경우가 있다. 주변 선언이나 문맥까지 봐야 한다.

Compiler야 어떻게든 처리한다고 쳐도 IDE, Formatter, Static Analyzer 같은 툴을 만드는 입장에서는 골치 아프다.

CppFront는 이런 부분도 좀 정리하려고 한다. 당장 선언 문법부터 다르다.

기존 C++의 함수 선언은 반환 타입부터 시작한다.

```cpp
int add(int a, int b)
```

반환 타입인 `int`가 앞에 오고, 그 뒤에 함수 이름과 Parameter가 붙는다. Cpp2에서는 함수 이름부터 적는다.

```cpp
add: (a: int, b: int) -> int
```

`add`라는 이름을 먼저 보고, 받는 값과 반환 타입을 순서대로 읽을 수 있다. 변수도 `이름: 타입 = 값` 순서로 적는다.

```cpp
x: int = 42
```

변수 이름 `x`가 앞에 오고, 타입과 초깃값이 뒤에 붙는다.

사람이 왼쪽에서 오른쪽으로 읽기 편하고, Parser도 다음에 나올 문법을 예측하기 쉬워진다.

Cpp2 문법에서는 Preprocessor나 Macro처럼 Parsing을 복잡하게 만드는 기능도 최대한 피한다. 대신 기존 C++의 현대적인 기능을 활용한다.

문법이 괜히 낯설어진 건 아니다. 사람이 읽기도 편하고 Compiler나 IDE가 다루기도 편하게 바꿔 보니 이렇게 된 거다.

## 2. Syntax

말로만 보면 감이 잘 안 오니 코드를 보자.

처음 보면 C++보다 Rust, Swift, TypeScript 같은 언어가 먼저 떠오른다.

생김새는 달라도 결국 C++로 바뀌는 코드다. 보다 보면 익숙한 개념이 여기저기 나온다.

### 2.1. 변수 및 객체

변수 선언은 `name: type = value` 순서로 작성한다.

```cpp
x: int = 42;
name: std::string = "Cpp2";
```

타입을 쓰기 귀찮으면 `:=`로 추론하게 할 수도 있다.

```cpp
x := 42;
name := "Cpp2";
```

기존 C++의 `auto` 같은 거다.

C++의 `int x = 42`, `int x(42)`, `int x{42}`처럼 초기화 방법이 여러 개로 갈라지는 대신, 선언과 초기화 문법을 최대한 일관되게 유지하려고 한다.

### 2.2. 함수

함수도 변수처럼 이름부터 시작한다.

```cpp
add: (a: int, b: int) -> int = {
    return a + b;
}
```

기존 C++과 순서가 반대다.

C++에서는 반환 타입부터 읽어야 하지만 Cpp2에서는 `add라는 함수가 int 두 개를 받고 int를 반환한다`는 순서로 읽을 수 있다.

반환 타입을 추론하게 만들 수도 있다.

```cpp
square: (x: int) -> _ = {
    return x * x;
}
```

`main`도 특별할 건 없다.

```cpp
main: () -> int = {
    std::println("Hello, CppFront!");
    return 0;
}
```

Parameter 없이 `int`를 반환하는 함수로 적으면 된다. 위 코드는 문자열을 출력하고 `0`을 반환한다.

### 2.3. 파라미터

Parameter는 Cpp2에서 특히 흥미로운 부분이다.

앞에서 봤듯이 기존 C++에서는 `T`, `T&`, `const T&`, `T&&`부터 직접 골라야 했다.

Cpp2에서는 Pointer나 Reference를 고르기 전에 Parameter의 **용도**를 표현한다.

- `in`: 읽기 전용. 기본값이다.
- `inout`: 값을 읽고 수정한다.
- `out`: 함수에서 값을 만들어 호출자에게 전달한다.
- `move`: 값을 소비하고 소유권을 넘긴다.
- `forward`: Perfect Forwarding에 사용한다.

읽기만 한다면 이렇게 작성한다.

```cpp
print_val: (x: int) = {
    std::println("{}", x);
}
```

`in`이 기본값이라 굳이 적을 필요도 없다.

값을 수정해야 한다면 그때 `inout`을 사용한다.

```cpp
increment: (inout x: int) = {
    ++x;
}
```

함수가 Parameter를 어떻게 사용하는지 기존 C++의 Reference 표기보다 직접적으로 보인다.

### 2.4. 클래스 및 타입

새로운 타입은 `type`으로 정의한다.

```cpp
point: type = {
    x: int = 0;
    y: int = 0;

    print: (this) = {
        std::println("({}, {})", this.x, this.y);
    }
}
```

여기서 좀 특이한 건 `this`다. Cpp2에서는 이것도 그냥 Parameter로 다룬다.

Member Function은 `this`라는 Parameter를 하나 더 받는 함수처럼 다룬다.

그래서 `this`에도 `in`, `inout`, `move` 같은 Parameter 규칙을 그대로 적용할 수 있다.

객체를 수정하는 Member Function은 다음처럼 작성한다.

```cpp
move_x: (inout this, dx: int) = {
    this.x += dx;
}
```

기존 C++에서 함수 뒤에 `const`를 붙이거나 ref-qualifier를 붙이던 것보다, 이 함수가 객체를 수정하는지 여부가 훨씬 앞에 드러난다.

### 2.5. 조건문과 제어 흐름

조건문도 잠깐 보자. `if`는 별다를 게 없다.

```cpp
if x > 10 {
    std::println("Greater");
}
```

괄호 없이 조건식을 바로 작성한다.

기존 C++의 `switch`보다 강력한 `inspect`도 있다.

```cpp
inspect x -> std::println(_);
```

`inspect`는 값의 형태를 분석해 비교하는 Pattern Matching에 가깝다.

C++의 `std::variant` 같은 타입을 다룰 때도 쓸 수 있다. 기존의 `std::visit` 대신 Pattern Matching으로 적는 방식이다.

## 3. Wrapping Up

기본 문법까지 훑어봤다. 처음 보면 이게 C++가 맞나 싶을 정도로 생김새가 다르다.

하지만 이 코드도 결국 기존 C++ 코드로 변환된다. C++ 컴파일러와 STL, 라이브러리도 그대로 사용한다.

겉모습이 바뀌어도 밑에서는 여전히 C++가 돌아간다는 얘기다.

cppfront는 기존 C++ 위에 새 문법을 올리는 실험이다. "하위 호환성 때문에 C++ 문법을 못 고치겠으면 문법을 하나 더 만들자"는 얘기다.
