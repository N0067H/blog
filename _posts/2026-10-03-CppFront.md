## 0. Intro

C++는 거의 40년이 넘게 하위 호환성을 유지한답시고 문법이 괴랄해지고 있고, Memory Safety도 해결하기 어렵다는 비판을 많이 받고 있습니다.

특히 Dangling Pointer, Use-after-free, Out-of-bounds 같은 문제는 조금만 실수해도 바로 Undefined Behavior로 이어지는데, 이걸 언어 차원에서 완전히 막기도 어렵습니다.

그래서 한동안은 기존 C++ 코드베이스를 Rust 같은 Memory Safe 언어로 전환해야 한다는 이야기도 꽤 많이 나왔습니다.

아무튼 이번에 소개할 **cppfront**도 이런 문제를 해결하려는 시도 중 하나입니다. ISO C++ 표준 위원회 의장이었던 Herb Sutter가 문법을 새로 짜되, 기존 C++ 생태계를 그대로 가져간다는 **cppfront**를 제안했습니다.

cppfront는 새로운 문법으로 작성한 코드를 기존 C++ 코드로 변환해주는데요. 그다음은 우리가 원래 쓰던 C++ 컴파일러가 컴파일하는 구조입니다.

그래서 cppfront를 컴파일러라고 부르기에는 조금 애매하고, Source-to-Source Compiler나 Transpiler에 더 가깝습니다. TypeScript 코드를 JavaScript로 변환해서 기존 JavaScript 생태계를 그대로 사용하는 것과 꽤 비슷하죠.

**cppfront**라는 이름은 Bjarne Stroustrup이 처음 C++을 구현할 때 만들었던 **cfront**에서 오마주해온 것 같습니다. cfront도 당시 C++ 코드를 C 코드로 변환해주는 방식이었으니 하는 짓도 묘하게 비슷하죠.

다른 말로 **Cpp2**라고도 부릅니다. 기존 C++ 문법을 **Cpp1**이라고 부르고, 새로운 문법을 **Cpp2**라고 구분합니다.

그렇다고 Cpp2가 C++을 버리고 새 언어로 갈아타자는 프로젝트는 아니고, 오히려 그 반대에 가깝습니다.

기존 C++ 코드와 생태계는 그대로 두고, 그 위에 더 단순하고 안전한 문법을 하나 추가해서 C++ 자체를 점진적으로 발전시켜 보자는 실험입니다.

## 1. Philosophy

그럼 CppFront가 어떤 방향을 바라보고 있는지부터 보겠습니다.

CppFront가 하려는 일을 간단히 말하면 C++을 지금보다 단순하고 안전하게 만드는 것입니다. 거기에 Compiler나 IDE 같은 툴이 코드를 다루기 쉽게 만드는 것도 중요한 목표입니다.

문제는 C++이 이미 수십 년 동안 사용된 언어라는 점입니다. 언어만 놓고 보면 마음에 안 드는 부분을 뜯어고치면 그만이지만, 현실에는 이미 어마어마한 양의 C++ 코드와 라이브러리가 깔려 있습니다.

CppFront는 이걸 버리고 새로 시작하는 대신 그대로 가져가는 쪽을 택합니다.

그리고 기존 C++에서 "이렇게 작성하는 게 좋습니다" 정도로 권장하던 것들을 아예 언어의 기본 동작으로 가져오려고 합니다. C++ Core Guidelines에서 권장하던 안전한 Parameter Passing이나 초기화 방식 같은 것들이 대표적입니다.

### 1.1. 하위 호환성을 포기하지 않는 진화

Rust나 Carbon처럼 새로운 언어와 생태계를 만드는 방법도 있지만, CppFront는 조금 다른 길을 택합니다.

기존 C++ 코드와 라이브러리는 그대로 사용하면서 그 위에 새로운 문법을 추가합니다. JavaScript 위에서 TypeScript를 사용하는 것과 비슷하게 생각하면 편합니다.

덕분에 Cpp2를 도입한다고 기존 C++ 표준 라이브러리나 서드파티 라이브러리를 포기할 필요는 없습니다.

별도의 FFI나 Binding, Wrapping 작업 없이 기존 C++ 코드를 Cpp2에서 사용하고, 반대로 Cpp2 코드도 기존 C++ 코드와 자연스럽게 섞어 사용하는 것을 목표로 합니다.

프로젝트 전체를 어느 날 갑자기 Cpp2로 다시 작성할 필요도 없습니다. 기존 코드는 그대로 두고 새로 만드는 부분부터 Cpp2를 적용하는 식으로 조금씩 넘어갈 수 있습니다.

수십 년 묵은 코드베이스가 여기저기 널려 있는 C++ 생태계를 생각하면 꽤 현실적이고, 어떻게 보면 굉장히 C++다운 접근이죠.

### 1.2. 올바른 행동을 기본값으로

기존 C++는 오랜 하위 호환성의 흔적이 언어 곳곳에 남아 있습니다.

초기화 규칙부터 implicit conversion, pointer, reference, const, move semantics까지 제대로 쓰려면 신경 써야 할 게 한두 개가 아닙니다.

함수 Parameter 하나만 해도 그렇습니다.

값으로 받을지, `const T&`로 받을지, `T&`로 받을지, `T&&`로 받을지 직접 결정해야 합니다. 각각 필요한 상황이 있기는 하지만, 결국 프로그래머가 "이 값을 어떻게 사용할 것인가"와 "그걸 C++에서 어떻게 구현할 것인가"를 같이 고민해야 하는 셈입니다.

Cpp2에서는 여기서 구현 방법보다는 의도를 먼저 표현합니다.

값을 읽기만 한다면 `in`, 수정한다면 `inout`, 함수에서 값을 만들어 호출자에게 전달한다면 `out`, 소유권을 넘긴다면 `move`, Perfect Forwarding이 필요하다면 `forward`를 사용합니다.

프로그래머는 이 Parameter로 무엇을 할지만 표현합니다. 그 의도를 실제 C++의 Parameter Passing 방식으로 옮기는 건 cppfront가 맡습니다.

반환값도 비슷합니다. Cpp2에서는 함수의 반환값을 기본적으로 그냥 무시할 수 없습니다. 기존 C++에서 `[[nodiscard]]`를 일일이 붙이던 것과 비교하면 기본값 자체가 반대로 되어 있는 셈이죠.

다만 Cpp2의 모든 변수가 기본적으로 immutable인 것은 아닙니다.

Parameter의 기본 모드인 `in`은 읽기 전용이고 Member Function의 `this` 역시 기본적으로 `in`이라 const처럼 취급됩니다. 그렇다고 일반적인 Local Variable까지 전부 immutable로 만들어 놓지는 않습니다.

Rust처럼 "일단 못 바꾸게 해두고 필요하면 `mut`를 붙인다"는 방식과는 조금 다릅니다. Cpp2는 특히 함수와 객체 사이에서 값이 어떻게 사용되는지를 명확하게 표현하는 데 초점을 둡니다.

### 1.3. Memory Safety 강화

C++에서 Pointer를 잘못 다루면 꽤 쉽게 Dangling Pointer나 Use-after-free를 만들 수 있습니다. 배열 인덱스를 잘못 계산하면 Out-of-bounds가 나기도 하죠.

더 골치 아픈 건 이런 실수가 항상 친절하게 에러를 내주는 것도 아니라는 점입니다. 많은 경우 그대로 Undefined Behavior의 영역으로 들어갑니다.

CppFront는 이런 문제 중 상당수를 언어 차원에서 잡으려고 합니다.

초기화되지 않은 값을 사용하는 것을 막고, 배열이나 컨테이너에 접근할 때 Bounds Checking을 적용합니다. Null Pointer Dereference나 Integer Division by Zero처럼 흔히 실수할 수 있는 동작도 검사 대상입니다.

물론 C++을 쓰면서 Low-level 작업을 아예 못 하게 막을 수는 없습니다. 하드웨어나 메모리를 직접 다뤄야 하는 상황에서는 원래 위험한 연산이 필요한 경우도 있으니까요.

그래서 위험한 동작 자체를 없애기보다는 **위험한 동작을 하고 있다는 사실이 코드에 드러나게 만드는 쪽**을 택합니다.

예를 들어 안전하지 않은 Cast가 필요하다면 평범한 코드 사이에 아무렇지 않게 섞어 쓰는 대신, 프로그래머가 의도적으로 안전 규칙을 벗어나고 있다는 것을 명시해야 합니다.

Rust의 `unsafe`가 떠오를 수 있는데, 접근 방식에는 차이가 있습니다. 하나의 `unsafe` 블록을 열어서 여러 안전 규칙을 한꺼번에 해제하기보다는 필요한 규칙만 좁게 해제하는 방향을 지향합니다.

야매로 풀자면 **안전한 코드가 기본이고, 위험한 짓을 할 거면 티 내면서 해라** 정도입니다.

### 1.4. Machine-friendly 문법 단순화

기존 C++ 문법은 사람에게도 어렵지만 Parser 입장에서도 썩 반가운 언어는 아닙니다.

Context-sensitive한 문법이 워낙 많아서 코드 일부만 보고는 이게 무슨 의미인지 결정할 수 없는 경우가 있습니다. 주변 선언이나 문맥까지 알아야 제대로 해석할 수 있는 거죠.

Compiler야 어떻게든 처리한다고 쳐도 IDE, Formatter, Static Analyzer 같은 툴을 만드는 입장에서는 꽤 골치 아픈 특성입니다.

CppFront는 문법을 새로 설계하는 김에 이런 부분도 단순하게 만들려고 합니다.

대표적인 게 선언 문법입니다.

기존 C++에서는

`int add(int a, int b)`

처럼 반환 타입부터 시작하지만 Cpp2에서는

`add: (a: int, b: int) -> int`

처럼 이름부터 시작합니다.

변수도 마찬가지입니다.

`x: int = 42`

처럼 `이름: 타입 = 값` 순서로 통일합니다.

사람 입장에서는 그냥 왼쪽에서 오른쪽으로 읽으면 되고, Parser 입장에서도 앞으로 무엇이 나올지 예측하기 쉬워집니다.

Preprocessor나 Macro처럼 Parsing을 복잡하게 만드는 기능도 Cpp2 문법 안에서는 최대한 피합니다. 대신 기존 C++에 이미 있는 현대적인 언어 기능을 활용하는 방향으로 갑니다.

Cpp2의 문법이 C++과 상당히 다르게 생긴 것도 단순히 문법을 예쁘게 바꾸고 싶어서만은 아닙니다.

사람이 읽을 때 덜 헷갈리고, Compiler나 IDE 같은 툴도 코드를 좀 덜 고통스럽게 이해할 수 있게 만들려는 것입니다.


## 2. Syntax

아무튼 설명이 꽤 길어졌으니, 이제 어서 실제 문법을 보겠습니다.

처음 보면 C++보다는 Rust, Swift, TypeScript 같은 비교적 현대적인 언어들이 먼저 떠오릅니다.

그래도 결국 C++로 내려가기 때문에 자세히 보면 C++의 개념들이 그대로 숨어 있습니다.

### 2.1. 변수 및 객체

먼저 변수 선언부터 보겠습니다. `name: type = value` 순서로 작성합니다.

```cpp
x: int = 42;
name: std::string = "Cpp2";
```

타입을 굳이 적고 싶지 않으면 `:=`를 이용해서 타입을 추론할 수도 있습니다.

```cpp
x := 42;
name := "Cpp2";
```

기존 C++의 `auto`와 비슷한 역할이라고 생각하면 되는 거죠.

C++의 `int x = 42`, `int x(42)`, `int x{42}`처럼 초기화 방법이 여러 개로 갈라지는 대신, 선언과 초기화 문법을 최대한 일관되게 유지하려고 합니다.

### 2.2. 함수

이어서 함수도 보겠습니다. 변수와 마찬가지로 이름부터 시작합니다.

```cpp
add: (a: int, b: int) -> int = {
    return a + b;
}
```

기존 C++과 비교하면 순서가 완전히 뒤집혔죠.

C++에서는 반환 타입부터 읽어야 하지만 Cpp2에서는 `add라는 함수가 int 두 개를 받고 int를 반환한다`는 순서로 그냥 왼쪽에서 오른쪽으로 읽으면 됩니다.

반환 타입을 추론하게 만들 수도 있습니다.

```cpp
square: (x: int) -> _ = {
    return x * x;
}
```

`main`도 특별할 건 없습니다.

```cpp
main: () -> int = {
    std::println("Hello, CppFront!");
    return 0;
}
```

### 2.3. 파라미터

이번에는 Parameter를 보겠습니다. Cpp2에서 꽤 재미있는 부분인데요.

기존 C++에서는 Parameter 하나를 넘기는 데도 `T`, `T&`, `const T&`, `T&&` 같은 걸 직접 결정해야 했습니다.

Cpp2에서는 Pointer나 Reference를 어떻게 쓸지보다 이 Parameter를 **어떤 용도로 사용할 건지**를 먼저 표현합니다.

- `in`: 읽기 전용. 기본값입니다.
- `inout`: 값을 읽고 수정합니다.
- `out`: 함수에서 값을 만들어 호출자에게 전달합니다.
- `move`: 값을 소비하고 소유권을 넘깁니다.
- `forward`: Perfect Forwarding에 사용합니다.

예를 들어 읽기만 한다면 그냥 이렇게 작성하면 됩니다.

```cpp
print_val: (x: int) = {
    std::println("{}", x);
}
```

`in`이 기본값이라 굳이 적을 필요도 없는 거죠.

값을 수정해야 한다면 그때 `inout`을 사용합니다.

```cpp
increment: (inout x: int) = {
    ++x;
}
```

기존 C++의 Reference나 const Reference를 직접 설계하는 것보다 함수가 Parameter를 어떻게 사용하는지가 훨씬 직접적으로 보입니다.

### 2.4. 클래스 및 타입

이제 클래스처럼 직접 타입을 만드는 방법도 보겠습니다. Cpp2에서는 새로운 타입을 `type`으로 정의합니다.

```cpp
point: type = {
    x: int = 0;
    y: int = 0;

    print: (this) = {
        std::println("({}, {})", this.x, this.y);
    }
}
```

여기서 눈여겨볼 부분은 `this`인데요. 이것도 그냥 Parameter처럼 취급됩니다.

이게 꽤 중요한 특징인데, Member Function을 뭔가 특별한 함수로 취급하기보다는 `this`라는 Parameter를 하나 더 받는 함수처럼 다룹니다.

그래서 `this`에도 `in`, `inout`, `move` 같은 Parameter 규칙을 그대로 적용할 수 있습니다.

객체를 수정하는 Member Function이라면 대충 이런 느낌입니다.

```cpp
move_x: (inout this, dx: int) = {
    this.x += dx;
}
```

기존 C++에서 함수 뒤에 `const`를 붙이거나 ref-qualifier를 붙이던 것보다, 이 함수가 객체를 수정하는지 여부가 훨씬 앞에 드러납니다.

### 2.5. 조건문과 제어 흐름

마지막으로 조건문과 제어 흐름을 간단히 보겠습니다. 기본적인 `if`는 크게 특별하지 않습니다.

```cpp
if x > 10 {
    std::println("Greater");
}
```

괄호 없이 조건식을 바로 작성합니다.

그리고 기존 C++의 `switch`보다 좀 더 강력한 기능으로 `inspect`가 있습니다.

```cpp
inspect x -> std::println(_);
```

`inspect`는 단순히 정수 하나 비교하는 `switch`를 예쁘게 만든 정도가 아니라, 값의 형태를 분석해 비교하는 Pattern Matching에 가까운 기능입니다.

특히 C++의 `std::variant` 같은 타입을 다룰 때 기존의 `std::visit`보다 훨씬 자연스럽게 표현할 수 있습니다.

## 3. Wrapping Up

아무튼 CppFront의 방향과 기본적인 문법을 살펴봤습니다. 여기까지 문법만 보면 C++과는 거리가 멀어도 너무 멀다는 생각이 들 수도 있습니다.

근데 재미있는 점은 결국 이 코드가 기존 C++ 코드로 내려가고, 기존 C++ 컴파일러와 STL, 라이브러리를 그대로 사용한다는 것입니다.

문법은 꽤 과감하게 뜯어고쳤는데 그 아래에는 여전히 C++이 있는 셈이죠.
